# Results

Every number in the reports comes from a file in this folder. Images, attention maps and caches that are too large for the repository (`*.npz`, `*.npy`, `data/`) are regenerated by the commands in the main README.

## environment/

| File | What it is |
|---|---|
| `pip_freeze.txt` | Exact package versions of the environment that produced every result |

## m1_smoke_test/

The first test of the environment: three prompts, 20 steps, guidance 7.5.

| File | What it is |
|---|---|
| `seed0.png`, `seed1.png`, `seed2.png` | One image per prompt; `seed2.png` ("A cat sitting on a wooden bench in a park.") shows no cat |
| `summary.json` | Versions, GPU, seconds per image, peak GPU memory, and the determinism check |

## m1_pipeline/

Notebook `01_data_and_embeddings.ipynb`: cleaning, text-to-embedding cache, retrieval, parity checks, sample tests.

| File | What it is |
|---|---|
| `summary.json` | Cleaning counts, retrieval recall, both parity checks and the list of sample captions |
| `caption_stats.png` | Caption length in CLIP tokens, and the 15 most common object categories |
| `samples/` | 15 generated images (5 captions x 3 seeds), each with a JSON of caption, seed, steps, guidance and timing |
| `samples_grid.png` | The 15 samples beside the real COCO photos |
| `timing.json` | Seconds per image measured on AC power (`scripts/time_generation.py`) |
| `parity_batch256_vs_batch1.png` | The same caption and seed generated from batch-256 and batch-1 embeddings: the small differences that led to one-at-a-time encoding |

## m1_word_timelines/

Notebook `02_word_timelines.ipynb`: attention recorded per word and per step for eight prompts.

| File | What it is |
|---|---|
| `summary.json` | Recorder-vs-stock check, commit steps per word, threshold sensitivity (0.7, 0.8, 0.9) and the final-step drop |
| `<prompt>.png` | The generated image for each prompt |
| `<prompt>_timeline.png` | The image, each word's attention share over time, and where each word lands |
| `settling_curves.png` | Correlation of each word's map with its final layout, step by step |

## m1_data/

`python -m w2w.prepare`: image preprocessing, frozen evaluation splits, data card.

| File | What it is |
|---|---|
| `data_card.json` | Every count and decision about the data (readable version: `docs/data_card.md`) |
| `eval_2000.csv` | The frozen evaluation split: 2,000 image-caption pairs, seed 2026 |
| `eval_500.csv` | Its first 500 rows, for multi-seed variance runs |
| `dev_500.csv` | The development split: 500 image-caption pairs for choosing settings, disjoint from the test set |
| `ref_2000.csv` | The reference split: 2,000 real photos used only as the reference for FID and KID, disjoint from both |
| `preprocessing_examples.png` | Before and after preprocessing for the widest, tallest, grayscale and smallest images |

## m2_pilot_steering/

`python scripts/pilot_steering.py`: does pushing a word's attention into a box move the object, and does that stop working once the word has committed? DDIM, 30 steps, guidance 7.5, seed 0, Faster R-CNN judge. Images and attention maps go to `data/m2_pilot_steering/`.

| File | What it is |
|---|---|
| `summary.json` | Settings, parity check, the calibration table (strengths 2.5 to 25, with and without end tokens) and the verdict: `NO_STEER`, so the main run and its figures were not produced |

## m2_pilot_editing/

`python scripts/pilot_editing.py`: three ways to change a picture partway through generation (swap a word, add a detail, drag an object with gradient guidance), each started at step k, and whether the word's commit step predicts when the change stops taking. DDIM, 30 steps, guidance 7.5, seeds 0 and 1. Images go to `data/m2_pilot_editing/`.

| File | What it is |
|---|---|
| `summary.json` | Settings, parity check, and per arm: success by start step, commit spread, leave-one-prompt-out accuracy, Spearman correlation and the verdict (swap `WEAK`, detail `NO_STEER`, drag `WEAK`) |
| `swap_runs.csv`, `swap_units.csv` | Word swap: one row per run (20 prompts x 2 seeds x 10 start steps) and one per prompt and seed |
| `detail_runs.csv`, `detail_units.csv` | Detail edit: the same, with CLIP edit scores and layout change, for 24 edits |
| `drag_runs.csv`, `drag_units.csv` | Drag: the same, for 12 prompts x 2 seeds x 8 start steps, with the box and final guidance loss |
| `<arm>_success_vs_start.png` | Success rate against the start step, and against the start step minus the word's commit step |
| `swap_example.png`, `detail_example_0.png`, `detail_example_1.png` | Strips of one unit at every start step: bicycle to motorcycle, the smiling cat, the cat in a red hat |

## m2_rewind_demo/

`python scripts/make_rewind_demo.py`: the rewind viewer's data. Each of 5 prompts is painted once with our own sampling loop, then branched with an edited prompt from steps 0, 3, 6, 9, 12 and 15. The viewer bundle (16.2 MB) is in `data/rewind_demo/`; open its `index.html`.

| File | What it is |
|---|---|
| `README.md` | Parity line, the per-example edit and scene estimates, bundle size, and notes from viewing the page |
| `demo.js` | Every number the viewer shows, including per-word attention maps (5.4 MB) |

## m2_rewind_live/

`python -m w2w.live`: Rewind running live on the laptop GPU, one sentence and one edit at a time, streamed to a local page.

| File | What it is |
|---|---|
| `README.md` | Seconds per painting and per branch, and notes on the branches, auto rewind, heatmaps and the safety checker |
| `v1_cat.png`, `v2_dog.png`, `v3_sunglasses_heatmap.png`, `v6_bus_heatmap.png` | Screenshots of the page |

## m2_pilot_moments/

`python scripts/pilot_moments.py`: two experiments built on rewind. **loss**: for 30 objects that a COCO caption names but the painting lacks, go back to several steps and repaint 8 times from each, to find the step after which the object stops coming back. **window**: 12 edits made from later and later steps, with and without a mask that freezes everything outside the edited words' region. Images go to `data/m2_pilot_moments/`.

| File | What it is |
|---|---|
| `summary.json` | Settings, and per arm: survival by step, moment-of-loss spread, early-warning correlation, edit and scene rates by step, and the verdicts (loss `MOMENTS`, window `NO_GAIN`) |
| `loss_failures.csv`, `loss_repaints.csv` | One row per failure (caption, object, share of repaints with the object at each step, moment of loss) and one per repaint |
| `loss_survival.png` | Share of repaints that recover the object, by rewind step, and the spread of the moment of loss |
| `loss_example_00.png`, `loss_example_01.png` | The base painting and one repaint from each rewind step for two failures |
| `window_runs.csv`, `window_units.csv` | One row per edit, seed, condition and start step, and the latest usable start per unit |
| `window_plain_vs_masked.png` | Edit taken and scene kept by start step, plain against masked |
| `window_hat_*.png`, `window_sunglasses_*.png` | Strips of the red-hat and sunglasses edits at every start step, plain and masked |

## m2_pilot_recall/

`python scripts/pilot_recall.py`: does an object word's commit step predict whether its object appears? Every dev_500 caption that names an annotated object is painted once (seed 0), and two detectors (Faster R-CNN v2, RetinaNet v2) judge each named object. Images go to `data/m2_pilot_recall/`, named by `caption_idx`.

| File | What it is |
|---|---|
| `instances.csv` | One row per named object: caption, object, commit step, early attention share, both detector scores and the judgement (present, missing or ambiguous) |
| `summary.json` | Counts, median commit by judgement, AUROC and within-class AUROC with bootstrap intervals for the commit step and the early share, and the verdicts (both `PREDICTS`) |
| `commit_vs_recall.png` | Distributions of the commit step and the early attention share, present against missing |

## m2_pilot_rescue/

`python scripts/pilot_rescue.py`: for the objects that pilot_recall found missing, going back to step 3, 6, 9 or 12 and repainting (rescue) against painting again from a new seed (regeneration), 4 tries each. Images go to `data/m2_pilot_rescue/`.

| File | What it is |
|---|---|
| `tries.csv` | One row per try: failure, condition, detector scores, fixed or not, LPIPS to the original, CLIPScore and sharpness |
| `failures.csv` | One row per failure and condition: fixed within 4 tries, fix rate, fixed with the scene kept, best LPIPS among fixes |
| `summary.json` | fix@1, fix@4, kept@4, cost and quality per condition, the paired comparisons, the sampler check and the verdict (`TRADE_OFF`, best rescue step 12) |
| `rescue_curve.png` | Failures fixed within 4 tries against the change to the original picture, per condition |
| `rescue_example_00.png` to `rescue_example_05.png` | The original and one try per condition for six failures |
